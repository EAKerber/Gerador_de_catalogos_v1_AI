# DB-05.18.1 — Linha de base visual e contratual

## Objetivo

Registrar o comportamento atual do checkpoint 1 do Incremento 05.18 antes de qualquer nova alteração de runtime na branch `agent/developer-b-05.18`.

Este checkpoint não corrige representação, não reorganiza a biblioteca e não adiciona componentes. Ele transforma o estado atual em uma matriz reproduzível para que os incrementos seguintes tenham uma referência objetiva.

## Teste

Arquivo executável:

```text
tests/browser-developer-b-baseline-05.18.1.test.js
```

Pré-condições:

1. servir a raiz do projeto em `http://127.0.0.1:8080`;
2. disponibilizar Playwright e um Chromium íntegro;
3. executar o teste com Node.js.

Exemplo:

```bash
python -m http.server 8080
node tests/browser-developer-b-baseline-05.18.1.test.js
```

Variáveis opcionais:

- `CATALOG_BASE_URL`: endereço do editor;
- `CATALOG_CHROMIUM_EXECUTABLE`: Chromium a utilizar;
- `CATALOG_DEVELOPER_B_OUTPUT_DIR`: diretório de saída, por padrão `/tmp/catalog-developer-b-05.18.1`;
- `CODEX_PRIMARY_RUNTIME_NODE_MODULES`: raiz alternativa dos módulos Node usados pelo runtime de teste.

## Matriz exercitada

O teste combina os cinco modos canônicos de `product-card` com dois estados responsivos:

| Estado | Largura × altura |
| --- | --- |
| amplo | 420 × 320 px |
| compacto | 280 × 390 px |

Modos:

- `standard`;
- `hero`;
- `technical`;
- `variants`;
- `data-only`.

Para cada uma das dez combinações são registrados:

- apresentação persistida e modo publicado no DOM;
- frame externo do card;
- frames de modelo dos slots `title`, `art`, `specifications` e `table`;
- união geométrica dos ocupantes renderizados em cada slot;
- geometria relativa em mídia de tela e de impressão;
- diferença máxima tela × impressão;
- colisões e overflows do relatório de publicação;
- screenshot isolado do card.

Também são registrados os defaults atuais de:

- `text`: alinhamento inicial, alinhamento vertical central, escala 100% e overflow por quebra;
- `icon`: escala interna 100%;
- `specification`: escala interna 100%;
- `CatalogDocument`: schema `1.16.0`.

## Saídas geradas

No diretório configurado, o teste produz:

```text
baseline.metrics.json
wide-standard.png
wide-hero.png
wide-technical.png
wide-variants.png
wide-data-only.png
compact-standard.png
compact-hero.png
compact-technical.png
compact-variants.png
compact-data-only.png
```

`baseline.metrics.json` usa dois estados:

- `pass`: nenhum desvio foi encontrado pelos critérios atuais;
- `divergence`: a execução terminou, mas registrou diferenças de paridade, colisão, overflow, defaults ou distinção geométrica.

Divergências visuais são dados deste checkpoint e não fazem o processo falhar automaticamente. Erros de página, erros de console, ausência de render ou modo não persistido continuam sendo falhas do teste.

## Critérios observados

A linha de base verifica explicitamente, na largura ampla:

- `hero` possui arte mais larga que `standard`;
- `technical` possui região de especificações mais larga que `standard`;
- `data-only` possui região de especificações mais larga que `technical`;
- `variants` empilha arte e especificações com a mesma largura.

A paridade tela × impressão usa geometria normalizada pelo frame do card. Diferenças superiores a `0,015` em posição ou dimensão relativa são registradas como divergência.
