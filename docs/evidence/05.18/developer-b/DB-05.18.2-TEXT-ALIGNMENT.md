# DB-05.18.2 — Texto: alinhamento e persistência

## Objetivo

Endurecer o alinhamento horizontal e vertical já introduzido no checkpoint 1 do Incremento 05.18, sem ampliar o editor tipográfico, alterar o frame do componente ou migrar `CatalogDocument 1.16.0`.

## Lacuna confirmada

O átomo `text` publicava corretamente `data-text-align`, o inspetor persistia `start`, `center` e `end`, e os seletores gerais convertiam esses estados em esquerda, centro e direita.

Entretanto, textos dentro de `footer-item` recebiam uma regra estrutural mais específica:

```css
.editor-component--footer-item > .component-children-layer > .editor-component--text .component-text {
  text-align: center;
}
```

A regra preservava a composição histórica do rodapé, mas mascarava escolhas explícitas feitas no inspetor. O documento podia registrar `align: "start"` ou `align: "end"` sem que o canvas ou o PDF representassem a intenção.

## Solução

Foi criada a camada `app/text-alignment-contract.js`, instalada antes da criação da store.

Ela possui quatro responsabilidades limitadas:

1. novos textos internos de `footer-item` recebem `align: "center"` como default estrutural real;
2. documentos legados cujo texto de rodapé ainda contém o antigo `start` não explícito são normalizados para `center`, preservando a aparência anterior;
3. mudanças futuras feitas pelo usuário recebem `alignExplicit: true`, permitindo distinguir uma escolha real de `start` do fallback legado;
4. seletores CSS específicos tornam `start`, `center` e `end` efetivos dentro do rodapé em tela e impressão.

`alignExplicit` vive em `props`, já extensível, e não exige mudança de schema.

## Compatibilidade

### Documento legado

Um texto de rodapé com:

```json
{
  "align": "start"
}
```

sem `alignExplicit` é interpretado como o antigo default estrutural mascarado e mantém a aparência central.

### Escolha explícita atual

Depois que o usuário escolhe **Início**, **Centro** ou **Fim**, o componente passa a persistir:

```json
{
  "align": "start",
  "alignExplicit": true
}
```

Essa intenção sobrevive a exportação, importação, desfazer e refazer.

### Outros textos

Textos autônomos e textos em cabeçalhos, cards ou áreas de composição mantêm o default anterior:

- horizontal: `start`;
- vertical: `center`;
- nenhuma alteração de frame;
- nenhum novo estilo tipográfico.

## Arquivos

### Runtime

- `app/text-alignment-contract.js`;
- `app/main.js` — carrega o contrato antes de instanciar `CatalogDocumentStore`.

### AuthoringKit

- `authoring-kit/runtime/text-alignment-contract.js`.

O runtime principal e o espelho são protegidos por comparação textual. O arquivo gerado `app/authoring-kit-files.js` precisa ser regenerado com `node tools/build-authoring-kit.js` em um ambiente executável antes de promover a branch.

### Testes

- `tests/browser-text-alignment-05.18.2.test.js`.

## Contratos cobertos

O conjunto de testes verifica:

- os três alinhamentos horizontais;
- topo, meio e base;
- default central do rodapé;
- escolha explícita de início dentro do rodapé;
- escolha explícita de fim dentro do rodapé;
- uma entrada de histórico por alteração;
- desfazer e refazer;
- frame externo inalterado;
- exportação e nova instanciação da store;
- análise segura de documento legado;
- permanência no schema `1.16.0`;
- equivalência entre canvas e mídia de impressão;
- identidade entre runtime principal e espelho do kit.

## Limites mantidos

Este incremento não inclui:

- escala tipográfica;
- política de overflow;
- editor rico;
- direção de escrita configurável;
- CSS livre;
- mudança de tipografia;
- novo componente.
