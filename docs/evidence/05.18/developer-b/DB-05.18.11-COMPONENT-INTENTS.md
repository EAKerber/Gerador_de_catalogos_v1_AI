# DB-05.18.11 — Descoberta por intenção: classificação

## Objetivo

Classificar os 16 tipos existentes em cinco intenções editoriais sem alterar IDs, categorias legadas, documentos ou a apresentação visual atual da biblioteca.

## Fonte declarativa

Foi criado:

```text
app/component-intent-registry.js
```

A taxonomia é separada do `CATALOG_COMPONENT_REGISTRY`. Ela referencia os IDs existentes, mas não copia definições, renderers, constraints ou campos.

## Grupos

### Página

- `catalog-header`;
- `catalog-footer`.

### Produto

- `product-card`;
- `art`;
- `art-gallery`;
- `specification`;
- `title-symbol`.

### Dados

- `data-table`;
- `legend-panel`;
- `legend-group`;
- `legend-item`.

### Comunicação

- `text`;
- `icon`;
- `separator`;
- `footer-item`.

### Estrutura avançada

- `layout-container`.

## Metadados dos grupos

Cada grupo declara:

- ID estável;
- rótulo;
- descrição;
- ordem;
- camada `primary` ou `advanced`.

Página, Produto, Dados e Comunicação são `primary`. Estrutura avançada é `advanced`.

Esses metadados serão consumidos pelo DB-05.18.12, mas não reorganizam a UI neste incremento.

## Validação

`CatalogComponentIntents.validate(registry)` detecta:

- tipo registrado sem classificação;
- classificação para tipo inexistente;
- grupo inexistente;
- grupo vazio.

A classificação atual possui:

- 16 tipos registrados;
- 16 atribuições;
- cinco grupos não vazios;
- nenhuma duplicação;
- nenhuma ausência.

## Manifesto de capacidades

Foi criado:

```text
app/component-intent-manifest-contract.js
```

Ele envolve `CatalogProjectManifests.buildCapabilitiesManifest` e adiciona:

```text
componentIntents.manifestVersion
componentIntents.groups[]
components[].intent
```

A projeção falha explicitamente se a taxonomia ficar incompleta após uma futura alteração do registro.

O schema de capacidades já permite propriedades adicionais, portanto não foi necessária alteração de schema.

## AuthoringKit e guia

Os dois arquivos possuem espelhos em:

```text
authoring-kit/runtime/component-intent-registry.js
authoring-kit/runtime/component-intent-manifest-contract.js
```

`tools/build-authoring-kit.js` passa a:

- copiar os arquivos;
- carregar registro, pacote e contrato em ordem;
- instalar a projeção antes de gerar `capabilities.json`;
- preservar `componentIntents` em `feature-inventory.json`;
- incluir intenção em cada componente do inventário;
- gerar no atlas uma tabela dos cinco grupos;
- manter a categoria legada como coluna separada.

## Biblioteca atual

A biblioteca ainda usa as categorias:

- Estruturas;
- Elementos;
- Peças internas.

Isso é deliberado. O DB-05.18.11 produz metadados consumíveis; o DB-05.18.12 altera a apresentação da biblioteca.

Nenhum tipo foi ocultado, movido ou renomeado neste incremento.
