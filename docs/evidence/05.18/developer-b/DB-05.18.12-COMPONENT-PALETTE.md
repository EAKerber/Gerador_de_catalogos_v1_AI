# DB-05.18.12 — Descoberta por intenção: apresentação da biblioteca

## Objetivo

Reorganizar a biblioteca de componentes com base na taxonomia criada no DB-05.18.11, reduzindo a exposição inicial de infraestrutura sem remover acesso, drag and drop, teclado ou inserção contextual.

## Distinção entre semântica e apresentação

A intenção semântica permanece definida por `CatalogComponentIntents`.

O caminho visual **Estrutura avançada** é uma decisão de descoberta, não uma nova intenção. Ele reúne:

- `layout-container`, semanticamente Estrutura avançada;
- todos os tipos cuja categoria legada é `Peças internas`, preservando suas intenções Produto, Dados ou Comunicação.

Exemplos:

- `specification` continua semanticamente Produto;
- `data-table` continua semanticamente Dados;
- `footer-item` continua semanticamente Comunicação;
- os três aparecem visualmente em Estrutura avançada.

## Apresentação inicial

A biblioteca exibe quatro grupos primários:

### Página

- `catalog-header`;
- `catalog-footer`.

### Produto

- `product-card`;
- `art`;
- `art-gallery`.

### Dados

- `legend-panel`.

### Comunicação

- `text`;
- `icon`;
- `separator`.

## Caminho avançado

O grupo recolhível **Estrutura avançada** contém:

- `layout-container`;
- `title-symbol`;
- `specification`;
- `data-table`;
- `legend-group`;
- `legend-item`;
- `footer-item`.

Na página, o grupo inicia recolhido. Em um contexto interno, ele abre automaticamente quando há peças avançadas compatíveis.

## Implementação

Foi criado:

```text
app/component-palette-intent-contract.js
```

O contrato envolve `CatalogEditorRenderer.prototype.renderPalette`.

O renderer canônico continua responsável por:

- decidir quais tipos são permitidos no contexto;
- gerar itens, receitas, componentes salvos e ações contextuais;
- publicar atributos de drag, teclado e inserção.

Depois da renderização original, o contrato:

1. coleta somente itens regulares com `data-insert-component`;
2. mantém os mesmos nós DOM;
3. remove apenas os contêineres de categorias legadas desses itens;
4. redistribui os nós nos quatro grupos primários e no grupo avançado;
5. preserva receitas, componentes salvos e ações contextuais;
6. adiciona busca e navegação.

Mover os nós em vez de recriá-los preserva:

- `data-component-type`;
- `data-insert-component`;
- `draggable="true"`;
- `tabindex="0"`;
- handlers delegados do módulo de interações.

## Busca

A busca usa nome e descrição já renderizados.

Comportamentos:

- filtra componentes, receitas e componentes salvos;
- oculta grupos sem resultados;
- abre Estrutura avançada quando contém um resultado;
- preserva o termo após rerender;
- `Escape` limpa o termo e restaura a biblioteca;
- `/` focaliza o campo quando o foco está na biblioteca.

O handler de `/` é vinculado uma única vez ao root persistente e localiza o campo atual após cada rerender, evitando closures para inputs removidos.

## Contexto

A organização respeita a lista produzida pelo renderer para o contexto atual.

No contexto de `product-card`, por exemplo:

- Produto: `art`, `art-gallery`;
- Comunicação: `text`, `icon`;
- Estrutura avançada: `title-symbol`, `specification`, `data-table`.

Nenhum tipo incompatível é apresentado.

## Estilo

Foi criado:

```text
styles/component-intents.css
```

A folha é carregada dinamicamente pelo contrato e contém apenas estilos da biblioteca:

- navegação e busca;
- cabeçalhos de intenção;
- contadores;
- grupo avançado recolhível;
- estados de filtro.

A UI é ocultada junto do painel lateral na impressão; não altera o PDF.

## Escopo do AuthoringKit

O contrato de apresentação é exclusivo do editor visual.

Ele não é copiado para `authoring-kit/runtime` e não é carregado pelo compilador autocontido, pois:

- depende de DOM, renderer e painel lateral;
- não altera documento, geometria ou compilação;
- a taxonomia semântica já está disponível no AuthoringKit pelo DB-05.18.11.

## Compatibilidade

O incremento não altera:

- IDs de componente;
- definições do registro;
- categorias legadas no manifesto;
- schema de documento;
- drag and drop;
- inserção pelo botão `+`;
- inserção por Enter ou Espaço;
- receitas;
- componentes salvos;
- ações contextuais.

## Limites mantidos

Não entram neste incremento:

- alteração de ícones;
- favoritos ou ordenação personalizada;
- persistência do estado aberto dos grupos;
- busca por tags externas ao texto renderizado;
- remoção de tipos;
- depreciação;
- mudança de schema;
- alteração do AuthoringKit compilável.
