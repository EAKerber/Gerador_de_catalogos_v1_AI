# DB-05.20.3 — Diagnóstico detalhado de referências

## Problema observado

O benchmark promocional terminava com `missingReferences: 1`, embora modelo, DOM, exportação e reimportação estivessem íntegros.

A referência foi localizada no `product-card` promocional. O card possuía conteúdo autônomo e `binding.productId: null`, estado que o próprio inspetor apresenta como **Conteúdo autônomo**. O validador anterior tratava tanto ausência deliberada de vínculo quanto ID explicitamente inexistente como `PRODUCT_REFERENCE_MISSING`.

## Correção

`CatalogDocumentValidator` passou de `1.0.0` para `1.1.0` sem mudança de `CatalogDocument 1.16.0`.

O relatório agora contém:

```text
references.missing   — ID obrigatório informado, mas inexistente
references.invalid   — referência existente, porém semanticamente incompatível
references.optional  — vínculo deliberadamente vazio e suportado
```

`summary.missingReferences` é derivado exclusivamente de `references.missing.length`.

### Vínculos opcionais

- `product-card` sem `productId`: `product / local-content`;
- `art` sem `assetId`: `asset / placeholder-without-asset`.

### Referências obrigatórias preservadas

Continuam sendo diagnosticados e bloqueados quando aplicável:

- produto explicitamente inexistente;
- asset explicitamente inexistente;
- linha de tabela ausente;
- legenda semântica ausente;
- variação ausente;
- token de cor ausente;
- linha comercial ausente.

Uma linha comercial existente, mas pertencente a outra variação, aparece em `references.invalid`, não em `missing`.

## Paridade e build

O runtime principal e `authoring-kit/runtime/catalog-validator.js` são idênticos. O AuthoringKit incorporado foi regenerado e o build voltou a ser idempotente.
