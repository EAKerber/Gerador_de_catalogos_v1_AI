# DB-05.20.5 — Aplicação conjunta de posição e tamanho

## Problema

O benchmark promocional corrigido exigia 44 ações separadas para informar `x`, `y`, largura e altura de 11 componentes. Cada valor alterava o documento e criava sua própria unidade de interação.

## Decisão arquitetural

Nenhuma segunda autoridade geométrica foi criada.

A implementação reutiliza `CatalogDocumentStore.applyComponentFramesBulk`, que já possuía:

- validação numérica;
- mínimos técnicos;
- clamp ao contexto pai ou à página;
- liberação de slot/layout quando necessário;
- atualização transacional;
- undo/redo único;
- suporte a múltiplos componentes.

A única ampliação no store foi permitir uma seleção mínima de um item:

```text
getBatchSelection(ids, 1)
```

O mesmo método continua sendo usado para aplicação em lote.

## Interface

O inspetor oferece um comando conjunto com:

- `X`;
- `Y`;
- largura;
- altura;
- botão **Aplicar posição e tamanho**.

Os campos são um rascunho local. Digitar ou escolher uma sugestão não modifica o documento nem cria histórico; somente o botão aplica a transação.

### Sugestões de posição

- topo seguro;
- base segura;
- coluna esquerda;
- coluna principal;
- faixa total.

As sugestões apenas preenchem os quatro campos. Elas não criam travas, não alteram conteúdo e continuam sujeitas a mínimos e limites na confirmação.

### Hierarquia do inspetor

O comando conjunto tornou-se essencial e sempre visível para seleção única. Os controles legados de alteração imediata por campo, mínimos, constraints e identificação permanecem em **Avançado**.

O inspetor usa uma grade de cinco regiões:

1. cabeçalho;
2. tabs;
3. comando conjunto;
4. painel ativo;
5. área avançada.

A quinta linha é instalada no bootstrap e evita sobreposição entre o comando e o painel ativo. Seleção múltipla mantém sua grade própria.

## Histórico

Uma confirmação gera exatamente uma entrada:

```text
Aplicar geometria da seleção
```

Undo restaura o frame anterior e redo restaura o frame aplicado. Clamp de mínimo ou limite permanece dentro da mesma entrada.

## Paridade

`app/document-store.js` e `authoring-kit/runtime/document-store.js` permanecem idênticos. O schema continua `CatalogDocument 1.16.0`.

## Regressão dedicada

Arquivo: `tests/browser-frame-application-05.20.5.test.js`.

A matriz valida:

- edição de rascunho sem mutação;
- aplicação dos quatro valores em uma transação;
- um único item na API canônica;
- uma entrada de histórico;
- undo/redo exatos;
- mínimos técnicos;
- limite da página;
- presets sem mutação antecipada;
- comando visível com **Avançado** fechado;
- schema inalterado;
- ausência de erros de página e console.

## Decisão

DB-05.20.5 está concluído.

A meta de no máximo 18 ações geométricas foi superada com 11. A meta total de 180 foi atingida exatamente. Não há evidência suficiente para justificar, neste momento, uma receita promocional completa apenas para reduzir mais ações.
